## Findings

1. **P2 — quiet-account batch can confirm a balance contradicted by a newer bank observation.** `packages/db/src/repos/month-close-reconciliation.ts:116-134` rejects a mismatching bank balance only when `balanceDate === asOf`. With a personally reconciled EUR 100 balance on September 15, a bank source reporting EUR 90 on September 29, no bookings/candidates, and a September 30 close, `movement`, `pending`, `unresolved`, `changed`, and booked-balance checks can all pass; September 29 is ignored and the batch creates a September 30 EUR 100 reconciliation. The canonical bank helper `packages/db/src/repos/bank-followups.ts:497-510,538-560` treats the observed date, or Vienna fetch date when absent, as the effective balance day and detects app/bank differences on that day. Exclude any contradictory bank observation effective after the prior personal check and on/before `asOf` (including the documented fetch-date fallback), leaving the individual reconciliation path available. Keep the proof inside the transaction/revision.

2. **P2 — the close writer accepts an unobserved revision.** `apps/server/src/api/month-close.ts:73-90` makes `sourceRevision` optional and tests it only if supplied. A direct `PATCH /api/month-close/2026-09` with `{ "close": true }` can persist a v1 snapshot and `closedAt` for the latest data without any caller supplying the stand it reviewed, provided steps are complete; changing source data between an older client view and this request is likewise accepted. The new UI supplies the revision (`apps/web/src/month-close/month-review.tsx:33-40`), but the server contract does not require it. Require `sourceRevision` when `close` is true, then compare unconditionally before the idempotent return; keep it optional for ordinary progress/decision patches.

A task click has no matching route in this standalone source head. The handoff explicitly assigns those `/heute/finanzcheck` routes to a coordinated reports/settings integration, so resolve by integrating that router contract before landing this UI or point at the existing route. This is a concrete cross-branch dependency, not a claim that the planned integration failed.
