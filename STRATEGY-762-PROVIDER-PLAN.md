## Smallest bounded adapter once source access is established

1. Add a server-owned strategy-specific reader, separate from `packages/market/src/yahoo.ts` and the regular security price table. Read only fixed series `NASDAQ100` from FRED's documented observations API (or an explicitly verified equivalent NDX EOD source); retain raw decimal text and parse to fixed integer `closeUnits` with `unitsPerPoint` matching actual published precision. Reject transformation, adjusted/total-return, non-USD, non-NDX, duplicate, nonpositive, unsafe, missing or conflicting rows. Hardcode the vetted source/index identity, not a user-provided symbol. Use bounded HTTP timeout/body/rate behavior from `packages/market/src/http.ts`; never log response bodies or an API key. Check provider access and permitted use before enabling automated refresh; an unavailable key/entitlement is an unavailable source, not a reason to fall back to a different index.
2. Build a **separate** versioned US-equity calendar manifest from Nasdaq Trader's annual publications and applicable alerts for the exact rolling 220-session history plus the current/next complete month. Record source URLs, retrieval/review time, covered interval, revision/hash and ET regular/early close for every listed date. Convert `America/New_York` close instants to canonical UTC `completedAt` with daylight-saving and early-close handling. Do not set `verifiedComplete: true` outside reviewed coverage or after a known calendar correction until the manifest is reconciled. If fully automatic official calendar ingestion is required, its stable data contract is still an unresolved source dependency; a licensed calendar provider would be a separate choice, not an invented requirement.
3. In the existing optional `StrategyEvidenceProvider` (`apps/server/src/api/portfolio-strategy.ts`, `apps/server/src/api/index.ts`), use one captured `asOf` and return `StrategyEvidence.status='verified'` only for a fully reviewed calendar window and 220 exact corresponding final closes. `latestCompletedSession` comes from that calendar, never from the newest quote; if its close is unpublished, return unavailable or `missing-close`. Set `closedAt` to that session's actual close boundary and `observedAt` to the server's successful retrieval time, making their different meanings explicit. Never claim the retrieval time is Nasdaq's original publication time. Supply complete `StrategyMonthCalendar` dates for monthly penultimate/last sessions with matching calendar ID; otherwise withhold the monthly candidate. Keep original observed snapshot in the existing decision writer so later FRED revisions do not silently change a recorded binding decision. Do not backdate newly obtained data into earlier `asOf` states.
4. Wire the adapter only at the server composition point (`apps/server/src/app.ts` / `createLedgerApi` options). Keep the existing default `MISSING_STRATEGY_EVIDENCE` whenever source identity, key, calendar, month coverage, precision, freshness or close publication cannot be established. Existing HTTP GET/POST never accept evidence supplied by a client. The UI already exposes source and data gaps. No strategy migration, broker integration, order action or market-price substitution is needed for this provider slice.

## Decision before source work

The close series is identifiable in official public documentation, but this environment could not inspect live responses. The exact FRED-to-NDX price-return mapping, use/licensing terms for automated consumption, and a verifiable complete actual-session feed/maintenance process remain evidence gaps. Do not represent the current `MISSING_STRATEGY_EVIDENCE` default as resolved until those items are checked with authorized access and an independent source review. The public Nasdaq calendar plus monitored alerts supports a bounded reviewed manifest; it does not prove an unattended evergreen calendar. No mandatory provider certificate or broker selection follows from this research.
