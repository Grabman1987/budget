## Implementation and limits

The existing ownership reader has an explicit delete policy; the default update policy is unchanged. Delete excludes reconciled, contact/trade-owned, document/statement-protected and invalid rows. Transfer pairs, ordinary bank references, payroll links and expected-payment links retain the canonical delete writer's existing semantics. The preview expands affected transfer sides, including unselected partners. A protected or missing partner excludes the entire pair. At most 500 affected booking sides are accepted; no partial pair is written to fit a limit. Selected and actual deletion native totals are distinct and use integer cents with explicit unavailable sums.

The existing `/bookings/bulk` path always recomputes eligibility in its locked transaction. New GUI callers must submit the exact preview revision; omission remains compatible for legacy callers but never bypasses eligibility, locks or pair protection. The legacy trade rejection code remains `invalid`, preserving its existing API contract; previewed callers receive the named `linked_trade` reason. The source fingerprint includes selected/affected IDs, complete current row/split states, ownership facts and a conservative global audit-head ABA fence. Any audited write, including Undo, can require a new confirmation. A stale submitted revision returns 409 before any write or audit. No second writer route or mutation framework exists.

The canonical `deleteBooking` writer performs each eligible deletion, preserving its transfer/expected-link changes, audit and Undo. One bulk audit group covers actual changes. Result IDs include any unselected counterpart actually deleted. Single GUI deletion also submits a source revision. Protected single-booking confirmation uses the existing form alert-dialog/focus scope; the draft and ordinary close/discard guard stay mounted. Bulk confirmation uses the existing bounded FormDialog with error/reload/explicit reconfirmation. Both reuse shared privacy-aware native formatting and design tokens.
