# #520 writer-plan review addendum — source contract, not validation

This addendum records the independent [writer-plan review](security-transfers-520-writer-plan-review.md) of the lost temporary plan. The reconstructed [base plan](security-transfers-520-writer-plan.md) does not claim byte identity with that file. These refinements are implementable without another owner financial decision.

1. **Eligibility.** Both endpoints must be live eligible investment accounts with `onBudget === false`, EUR account cost basis and the existing date/closed-account rules for a new write. `role === 'investment'` alone is insufficient: the schema permits an on-budget account with that role. A current closed account may still participate in historical read projection; read replay must not use today's write eligibility as a historical filter. An on-budget securities transfer is outside this initial no-envelope-action scope.

2. **Read projection versus mutation locks.** Split the consistent fact/replay loader from the mutation eligibility check. A later reconciliation lock blocks backdated writes but must not hide otherwise valid historical cost and returns. `portfolio-summary.ts::positionCost` and `realizedByPosition`, including sold positions and snapshot redundancy, need pair-aware dated cost. `portfolio.ts::holdingValuationRead` and `valuationSeries`/domain `series.ts` cost fallback need the same pair facts while retaining their present moving-average valuation fallback even if selected analytical cost uses FIFO. Do not feed a selected-method figure into a consumer whose existing policy is moving average. Both `portfolio.ts::portfolioFlows` branches, securities and depot, must classify paired legs **before gross daily flow aggregation**: two-sided inclusion is internal with no gross contribution/withdrawal; one-sided inclusion uses signed transfer-date value. This classification must reach contribution facts, TTWROR and XIRR for account/depot/security selections. Keep unpaired deliveries distinct. Use stored dated quote/FX quality policy for one-sided value; missing required valuation makes that scoped return unavailable, but does not by itself invalidate the basis transfer. Never fetch a quote in the writer or put market value in zero-cash trade amount.

3. **Affected scope and CAS.** For edits and undo, seed affected accounts and securities from **both before and after** row snapshots. Expand pre-mutation connected components, perform the mutation, then validate the union of those accounts and the post-mutation components. Removing the last connecting pair must not drop the detached side with dependent events. A security-ID change affects both old and new securities. Include adjacent tombstoned pair/leg identities and latest audit revisions in CAS facts for those seeds, even though only live pairs enter economic replay; a new adjacent pair must invalidate the token. Keep expansion bounded and inside the same transaction. Pair guards also cover generic `entities.ts` account/security/holding writes and audit restoration; only financial field changes need financial replay. Full grouped invariants run after undo/redo, including `force`; formerly paired tombstoned legs cannot be independently reused in a way that breaks redo. Preserve settlement-history checks from the reviewed reader.

4. **Same-day order.** Allocate a positive safe integer creation order including tombstones and persist exactly the order used for proposal replay. Pair-to-pair order follows that value. Preserve native buy-first and per-account SQLite `(date,id)` order. Accept multiple native rows and independent activity on the same day. For participating accounts where native/pair interaction placement is not established and changes outcome, return `ambiguous_pair_order` before assigning replay sequences. Do not impose one-native-event-per-day, invent timestamps or add an order table. Preview and post-insert reread must use the same placement contract.

5. **Two distinct hashes.** Define a versioned canonical **intent** hash over security, source/destination, date, integer units, normalized optional reference and material semantic choices. Exclude preview token and transport-only metadata, so a same-key retry with a refreshed preview still returns the original result. The separate **fact fingerprint** binds preview scope/version, exact proposed fields and full current affected suffix; it is a stale-state condition, not the durable action identity. Look up the idempotency key, including deleted pair rows, first inside the transaction: same intent returns current live/undone state, changed intent conflicts. Export the relation through the schema barrel so generic audit can discover and restore it. No separate preview session/table, new role, step-up policy or external approval service is needed.

Migration 0053 remains unreserved. No schema, writer, API, runtime check, test, build or DB operation was performed by this documentation checkpoint. Stage A executable acceptance and activation remain open.
