## Existing mutation and undo boundary

`repos/trades.ts` create/update/delete/bulk, method changes in `repos/investment-preferences.ts`, operator/import/savings callers, relevant snapshot/account/security mutation and audit restoration must invalidate stale previews and replay affected pair lineage. Linked delivery legs cannot be independently edited or deleted; require grouped undo. Earlier native buy/sale/split changes and later events may commit only if full connected replay remains valid. Backdated reconciliation locks block mutation. A method change must revalidate all affected paired components or return typed conflict. Canonical positions cannot continue treating an incoming zero-amount delivery as a zero-basis buy.

Generic `repos/audit.ts` currently guards cash `booking.transfer_id` groups, not security pairs. Disallow single-entry undo of the pair row or either linked leg; group undo/redo reverts all three tracked rows atomically and rechecks membership, settlement, locks and full later replay, including force. Insertion order out/in/pair means reverse undo removes the pair before legs, and redo restores legs before pair. Reject an undo that strands dependent sales/transfers. Pair identity, original creation order and intent remain in snapshots. Put reusable pair checks in `repos/invariants.ts`, separate from the cash-transfer invariant.
