## Finding

**P2 — A profile refresh consumed during a dirty draft is never applied once that draft becomes clean.** `apps/web/src/pages/profile-settings.tsx:118-124` sets `seenSaved` whenever the query supplies a new `saved` object, but updates `base` and `draft` only if the form is clean at that instant. If the owner has changed region from empty to Wien, then a background profile refresh brings a different name from another device (Alice → Bob), the dirty form correctly keeps its draft but marks Bob as seen. If the owner reverts region to empty, `dirty` becomes false against the old `base` (Alice), yet `saved === seenSaved`, so the clean form continues to display Alice and never adopts Bob. A later name keystroke creates a partial name PATCH against the stale display (`profile-settings.tsx:111-116,158-163`) and can overwrite Bob, although there was no remaining local draft when the refresh became eligible to apply. This stale-clean-state path is introduced by replacing the old query-keyed form remount with the `seenSaved` reconciliation; it is distinct from the documented lack of same-field cross-device CAS during an active edit. Minimal fix: while not busy, reconcile any current `saved` that differs from `base` as soon as the draft is clean, even if that `saved` object was observed earlier during a dirty state. Continue retaining the draft while dirty and retain the partial PATCH behavior.
