# Inflation basket settings (report 2.4, part A)

`/einstellungen/warenkorb` owns category inclusion and payee exclusions. The report links to it and reads the same settings for the headline, contributions and basket. Changes use the existing budget write/undo UI and invalidate ledger queries.

The nullable category `inflation_trailing_mean` remains the method selector: null = automatic, false = contracts, true = trailing mean. Additive owner choices live as validated JSON in the existing audited `app_setting` row `inflation.basket`, keyed by category ID: nullable `inclusion` (`always` / `never`) and `excludedPayeeIds` (including null for bookings without a payee). Missing settings mean automatic inclusion and no exclusions. No schema migration, dependency or real-data preset is added.

Automatic selection is limited to need-class fixed costs and regular periodic obligations. Want/future require Always; Always still needs usable price history and spending. One-off schedules remain excluded. Monthly implicit contracts need six bills, quarterly/half-yearly/yearly two. Due-day shifts of up to twelve days and a missed cycle are tolerated, but at least one directly observed interval is required so yearly bills are not mistaken for missed half-yearly bills. Yearly bills count a changed price immediately; shorter cycles retain the existing two-charge confirmation against outliers. Prices use the existing integer-cent monthly-equivalent function.

Payee exclusions filter the eligible ledger charges before implicit derivation, matching, trailing means and spending weights; stored contracts of excluded payees are also removed. Refunds of retained payees remain netted. No payee/category/memo name implies debt interest: the owner must exclude the relevant payee explicitly. This task adds no memo-rule editor.

Bulk PUT `/api/inflation-basket` validates strict, bounded changes and verifies live expense categories/payees in one transaction. Category method updates and the JSON setting share one audit group; any invalid member rolls all changes back. Undo/redo follows the existing app-setting audit semantics. Settings are current preferences applied to the entire report history, not effective-dated basket versions.

## Annual basket view (part C)

Calendar-year columns show the mean of observed monthly-equivalent prices, rounded once to integer cents. ## CPI sub-index method (part B, 2026-10-05)

Settings offer VPI-Teilindex for variable categories explicitly included with Always. One or two searchable ECOICOP class codes can be selected; shares are integer basis points, strictly positive, distinct and sum to 10000. One class receives 100%. Method and mapping live in the existing audited `inflation.basket` app_setting; the existing trailing-mean field remains unchanged and readable. Updates preserve inclusion and excluded payees. No migration or dependency is added.

Each class is rebased to its first common monthly observation before combining its price relatives with the selected split. The category then enters the existing annual chained household basket with the household's own included net spending weight. Source weights never enter this calculation. The total VPI remains a separate benchmark; sub-series cannot become the headline reference. CPI basket prices/history/year means are displayed as index values, never EUR amounts. If a selected spending category has no CPI history, the headline is unavailable; a publication lag or gap ends the basket at the last common continuous month, without freezing an invented price.

The existing loader now reads [Statistik Austria's detailed COICOP 2018 backcast on base 2020](https://data.statistik.gv.at/web/meta.jsp?dataset=OGD_vpi20c18_VPI_2020COICOP18_1) and the existing base-2025 file. Both contain monthly public open data, CC BY 4.0. The older division-only CSV remains parseable. Each class uses its own annual base-year factor when chaining; overlapping old months win. The refresh stores `vpi` and `vpi:<selection-code>` atomically in the existing table and backfills missing sub-series even if the total was recently refreshed. Production fetches remain monthly; CI uses only synthetic recorded-layout CSV responses.

Supported selection codes preserve the owner's ECOICOP vocabulary: 01.1 food, 07.2.2 fuel, 11.1 catering, 12.1.3 personal-care articles, 12.5 insurance services. In the published COICOP 2018 layout these are respectively 011, 0722, 111, 1312 and 121. The mapping is explicit; old 12.1.3 must never be read as new dwelling insurance. Further classes can be added to the same small catalogue when requested.

## Category explorer (part B2, 2026-10-05, evening)

Report 2.4 separates “Warenkorb vs. VPI” from “Kategorie-Explorer”. Explorer selection defaults to the basket categories, including explicit Always choices, and is local to the view. All expense categories remain selectable regardless of headline membership. Each selected category has its own index chart and stored matching CPI benchmark, with October 2023 = 100. Contract prices reuse the very same `personalInflation` annual chain and successor resolver as the headline. Missing October 2023 prices or fewer than thirteen closed months do not invent a later baseline.

The existing audited COICOP mapping can now be saved independently of the basket method, including clearing it for a total-CPI comparison. One/two-class validation and shares remain unchanged. Mapped categories use existing `cpiPriceLevels` and stored sub-series; unavailable mapped history stays unavailable. Only categories without a mapping use “Gesamt-VPI (kein Teilindex)”. No new loader, migration, dependency, provider API call or booking is added. The minimal shared read-model change constructs eligible price histories once for all categories and selects the headline subset afterward; its inclusion/method/payee rules remain unchanged.

Without contract prices, own observations use integer-cent net spending per booking; regular variable purchases are not inferred to be contract prices for the explorer. The line is explicitly labelled “Ausgaben je Buchung” because purchase mix and physical quantity per booking remain unknown. Counts deduplicate category splits by booking ID and count expense bookings, with retained refunds netted in spending. Comparable complete unit observations can use a common integer scale in the pure domain model; the current ledger has no physical-unit capture, so the application exposes booking counts only. Stored contracts and trailing means do not claim quantity attribution.

Price difference is own index change minus reference index change, in percentage points since the baseline. For booking/unit observations the additive volume effect is spending change minus the own average-price change; it includes the price/quantity interaction. Its displayed share uses **spending change minus CPI change** as denominator, explicitly named in the column; it can be negative or exceed 100%, and a zero/missing denominator is unavailable. This avoids mixing a price-only gap with a spending-volume contribution. Missing values display a dash. The fixed note keeps interpretation with the owner: “Mehr Fahrten erhöhen die Treibstoffkosten, nicht den Preis – Mengeneffekte selbst einordnen.” Calendar-year better/worse verdicts are replaced by neutral signed differences.
