## Envelope budget calculations

The monthly category activity cell `sum-amount-{category}` sums signed transaction amounts for that category in the month, joining accounts and excluding off-budget accounts. The transaction view is `v_transactions_internal_alive`, so any further filtering is defined by that view. Source: [base.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/base.ts#L133-L149).

For an expense category, source code implements:

```text
current leftover = current budgeted + current signed activity
                 + (prior carryover enabled ? prior leftover : max(prior leftover, 0))
```

Positive prior money carries forward even if the carryover flag is off. Prior negative balances carry into the category only with carryover enabled. `leftover-pos` is `max(leftover, 0)`. Source: [envelope.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/envelope.ts#L33-L75).

For each expense category with carryover off, the next month summary separately adds `min(prior leftover, 0)` into `last-month-overspent`; carryover categories are excluded. Let `I` be current income activity, `P` prior month To Budget, `H` selected held funds, `O` the sum of non-carried negative prior balances, and `B` total expense assignments. The current formula is:

```text
available-funds = I + P + H
To Budget = available-funds + O - B - H
```

`total-budgeted` is stored as the negative of expense assignments. When a hold is selected, `H` appears both in `available-funds` and as a subtraction, so it is not budgetable this month. Source: [envelope.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/envelope.ts#L98-L206).

Synthetic example: prior category leftover is -$25 and carryover is off. Next month's category starts from zero prior carry, while `last-month-overspent` is -$25, lowering To Budget by $25. If carryover is on, next category leftover starts with -$25 and that shortfall is omitted from `last-month-overspent`; this avoids applying the same deficit twice. If prior leftover is +$40 and carryover is off, the next month's category begins with +$40.

Income activity adds into available funds, and leftover To Budget flows from the prior month. `buffered-auto` sums activity from income categories whose carryover flag is true. `buffered-selected` uses the manual buffered amount when nonzero; otherwise it uses the automatic sum. Thus the income-category carryover flag also acts as an automatic hold selector in envelope mode. Source: [envelope.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/envelope.ts#L104-L127), [envelope auto hold](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/envelope.ts#L162-L190), [actions.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/actions.ts#L785-L799).

Manual holds modify the current month's `buffered` value. `holdForNextMonth` only writes while To Budget is positive. Its delta clamp prevents a buffer below zero or above current positive To Budget; `resetHold` writes zero. A held amount becomes available through the following month's `from-last-month` dependency. Documentation allows chained month-ahead holds by holding month by month. Sources: [actions.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/actions.ts#L31-L41), [actions.ts (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/actions.ts#L486-L516), [budgeting guide](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/index.md#L40-L57).

## Tracking mode and money movement

Tracking category balance uses `budgeted + activity + (carryover ? prior leftover : 0)` for expenses and `budgeted - activity + carryover` for income categories. Carryover defaults false. The summary's `total-saved` is budgeted income minus budgeted expenses; `real-saved` is actual income minus actual expenses. These values are not account balances or net worth. Sources: [tracking.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/tracking.ts#L11-L63), [tracking summary](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/tracking.ts#L91-L141).

`transferCategory` changes assignments without creating transaction activity. `coverOverspending` caps coverage at the smaller of the negative category amount and positive source balance. A subtle API edge is that `amount ? ... : full deficit` treats an explicit numeric zero as omitted. Source: [actions.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/actions.ts#L518-L575), [actions.ts (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/actions.ts#L643-L677). `copyPreviousMonth` copies assignments, not balances; it skips hidden categories/groups and skips income categories in envelope mode. Source: [actions.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/actions.ts#L218-L242).

## Credit cards, transfers, and refunds

The official Actual documentation says credit cards are ordinary accounts with negative balances. Purchases are categorized to expense envelopes at purchase time; transfers between on-budget accounts, including paying a card, do not change total on-budget funds. It recommends on-budget accounts for revolving cards, a pay-in-full workflow without a dedicated card category, and a distinct debt category when carrying debt. For debt rollover, the guide cautions that a carried negative category balance should not also reduce To Budget because the negative account balance already reduced on-budget cash. These are guidance and examples, not constraints enforced by a special credit-card budget formula. Sources: [credit card overview](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/credit-cards/index.md#L19-L52), [paying in full](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/credit-cards/paying-in-full.md#L3-L9), [paying in full (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/credit-cards/paying-in-full.md#L63-L82), [carrying debt](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/credit-cards/carrying-debt.md#L3), [carrying debt (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/credit-cards/carrying-debt.md#L47-L71).

Returns and reimbursements are documented separately. In the referenced envelope formula, no special refund branch exists; signed transaction activity updates the category. The CSV records this as documented plus source-confirmed formula evidence, with the exact outcome depending on how a return transaction is categorized. Sources: [returns and reimbursements](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/docs/docs/budgeting/returns-and-reimbursements.md#L1-L57), [base.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/base.ts#L133-L149).

## Targets, templates, schedules, and rules

Monthly budget rows persist `amount`, `carryover`, `goal`, and `long_goal`; category records persist serialized `goal_def`, plus `template_settings` identifying notes/UI source. Migrations add goal fields to both budget tables and the category, then long-goal and template-source metadata. This is a real schema evolution, not a single normalized goal table. Sources: [DB types](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/db/types/index.ts#L55-L80), [DB types (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/db/types/index.ts#L216-L242), [goal migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1694438752000_add_goal_targets.sql#L3-L5), [goal context migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1720665000000_goal_context.sql#L3-L4), [template source migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1754611200000_add_category_template_settings.sql#L3-L5).

Templates support fixed/simple, periodic, refill, copy, average, percentage, date-bound `by` and `spend`, schedule, remainder, limit, and goal forms. Application processes priorities, typically leaves nonzero assignments intact unless forced, bounds funding to To Budget in envelope mode or total-saved in tracking mode, and distributes residual amounts by remainder weights. Dry-run intentionally skips the available-funds clamp to show demand. Sources: [template types](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/types/models/templates.ts#L1-L124), [goal-template.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/goal-template.ts#L17-L36), [goal-template.ts (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/goal-template.ts#L217-L355), [goal-template.ts (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/goal-template.ts#L361-L386).

Schedule automation can link by stable ID with trimmed name fallback, read the attached rule's date/amount conditions, apply a fixed or percentage adjustment, and use rule actions (including splits and balance-of formulas) to estimate category impact. Sinking contributions vary by schedule recurrence and next due date; completed and past schedules are excluded or reported. Sources: [schedule-template.ts](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/schedule-template.ts#L34-L165), [schedule-template.ts (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/schedule-template.ts#L166-L303), [schedule-template.ts (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/server/budget/schedule-template.ts#L315-L420), [types](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/types/models/schedule.ts#L5-L43), [rules](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/types/models/rule.ts#L5-L19), [rules (additional)](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/types/models/rule.ts#L59-L180).

## Data relationships and migrations

Current entity types connect category to group and optional income status; transactions connect to account, optional category, transfer, parent/split children, and schedule; schedules connect to rules. Envelope and tracking monthly assignments live in separate `zero_budgets` and `reflect_budgets` tables, both keyed by month and category. `zero_budget_months.buffered` stores envelope holds. Rules and schedules have separate migration-created tables; schedules also have next-date/json-path state, and transactions gained a schedule reference. Sources: [entity types](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/types/models/category.ts#L3-L14), [transactions](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/src/types/models/transaction.ts#L8-L39), [budget migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1632571489012_remove_cache.js#L7-L23), [rules migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1597756566448_rules.sql#L3-L10), [schedule migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1618975177358_schedules.sql#L3-L26), [split parent migration](https://github.com/actualbudget/actual/blob/d5d6035a8f5867717a80635d270fbe64e370ea08/packages/loot-core/migrations/1608652596043_parent_field.sql#L3-L11).

## Coverage limits and open edges

This review inventories core budget calculation and key transaction/schedule relationships. It does not attempt all reporting, bank-sync, import, reconciliation, multi-currency, forecast, account-group, or UI behavior. The credit-card debt model is primarily documented guidance plus ordinary account/category mechanics; there is no YNAB-style automatic card-payment envelope calculation in the cited envelope engine. The focused `actions.test.ts` does not appear to assert `coverOverbudgeted`; a targeted test should cover full and partial coverage, zero/negative inputs, and over-budget category balances. The clamp path should also be tested for an explicit zero amount, negative adjustment, no positive To Budget, chained holds, and auto-held income combined with a manual buffer override. No external account server or private application values were accessed.
