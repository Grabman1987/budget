Root `package.json` identifies a private monorepo package version `0.0.1`, MIT, and describes Actual as local-first. ## Integration boundary

Actual is split across packages. The browser/desktop UI is in `packages/desktop-client`; portable ledger business logic and SQLite/IndexedDB platform layers are in `packages/loot-core`; `packages/sync-server` is a separate Express service that hosts sync and provider credential/API integrations. The root scripts distinguish `start:browser` from `start:server` (`package.json:20–34`). Do not treat the browser app source as containing the whole bank connection: the core client sends provider requests through the configured server, and sync server provider apps implement those endpoints. Docs explicitly say linked-bank integration requires `actual-server` (`packages/docs/docs/advanced/bank-sync.md:3–20`).

There is a useful division: users can enter and import ledger transactions locally, but linked bank providers need a reachable sync server and provider credentials. E2EE covers the budget file payload, not provider tokens stored separately on the server (`packages/docs/docs/advanced/bank-sync.md:3–12`; `packages/docs/docs/getting-started/sync.md:17–29`). Server administrators with direct database access can read these tokens. This boundary should be reflected in any feature comparison or security design.

## Ledger semantics and relevant source

- `packages/loot-core/src/types/models/transaction.ts:8–39` defines the transaction shape: string ID/account/date, `IntegerAmount`, optional payee/category/notes/imported ID, split parent/child links, transfer link, cleared and reconciled flags, schedule and tombstone. `packages/loot-core/src/types/models/account.ts:1–14` carries on/off-budget classification and last reconciliation metadata.
- Splits are parent plus subtransactions; docs require child sums to equal parent and describe even remainder distribution into empty splits, proportional distribution across entered splits, and cent remainder allocation (`packages/docs/docs/transactions/split-transactions.md:5–42`). Transaction API docs say child rows need full required fields and only process when the parent has `is_parent: true` (`packages/docs/docs/api/reference.md:175–212`). The behavior is in `packages/loot-core/src/shared/transactions.ts` and `server/transactions/merge.ts`; merges preserve child rows when the retained row is not a split (`merge.ts:110–194`).
- Transfers are implemented as linked equal/opposite records by `packages/loot-core/src/server/transactions/transfer.ts:addTransfer` (`47–93`); update/remove paths keep the pair coherent (`95–172`). Same-budget-class transfers clear categories; cross-class transfers keep budget-side category semantics (`24–45`). Docs explain date and cleared/reconciled independence and optional date synchronization (`packages/docs/docs/transactions/transfers.md:40–75`). Split parent transfers are skipped; transfer generation is expected via children (`transfer.ts:47–54`).
- Reconciliation uses cleared totals and a separate reconciled/locked status. UI calculates `targetDiff = targetBalance - cleared` (`packages/desktop-client/src/components/accounts/Reconcile.tsx:40–53`), then the lock action is only offered when the difference is zero (`87–110`). Docs warn that users must click Lock Transactions to complete reconciliation; unlock reverts status to Cleared (`packages/docs/docs/accounts/reconciliation.md:13–55`). A transfer's two halves have independent cleared/reconciled states because each account reconciles against its own statement (`transactions/transfers.md:51–55`).
- Payees are regular entities, and transfer payees are keyed to an account by `transfer_acct`. See API reference `packages/docs/docs/api/reference.md:600–614` and server `packages/loot-core/src/server/accounts/payees.ts`; payee CRUD is in `packages/loot-core/src/server/payees/app.ts`.

## Import, dedupe, exports and API

- Parser dispatch in `packages/loot-core/src/server/transactions/import/parse-file.ts:104–134` supports `.qif`, `.csv`/`.tsv`, `.ofx`/`.qfx`, `.xml` (CAMT). `ParseFileOptions` at lines `93–102` exposes headers, delimiter, missing-payee fallback, payee/memo swap, skipped lines, notes and encoding. CSV implementation continues at lines 136 onward. UI mapping is `packages/desktop-client/src/components/modals/ImportTransactionsModal/` (field mappings, date selection and amount transforms). The docs describe CSV fields, date format, delimiter, flip amount, inflow/outflow columns and multiplier (`packages/docs/docs/transactions/importing.md:11–35`).
- OFX maps FITID, date, amount, type, name and memo (`packages/loot-core/src/server/transactions/import/ofx2json.ts:105–124,155–189`); QIF parses date, amount, check/number, memo, payee, category and split divisions (`qif2json.ts:22–109`). CAMT uses `xmlcamt2json.ts` through the parser dispatcher.
- Import matcher `packages/loot-core/src/server/accounts/sync.ts:833–1033` normalizes and runs rules, attempts account-scoped `imported_id` first (`879–897`), then queries same-account, equal-amount transactions dated from 7 days before through 7 days after (`900–965`). Candidates sort by absolute date distance; rows with payee ID match in next pass; final pass takes first unused candidate (`968–1025`). In strict ID mode, if both incoming and existing imported IDs are set but the ID did not match, fuzzy dedupe is skipped (`908–942`). `reconcileTransactions` defaults `defaultCleared=true`, `updateDates=false` and skips overwriting matched reconciled transactions (`637–648,678–684`). Matched rows preserve existing payee/category/notes if present, fill gaps from import, retain cleared with OR semantics, and update imported ID/payee metadata (`692–728`). Import can update parent split children cleared/date states (`730–751`).
- Deleted transaction preference is account-scoped; exact matches may search tombstones depending on `reimportDeleted` (`sync.ts:845–852,879–889`). Explicit `transactions-import` routes through undoable mutator and passes import options (`packages/loot-core/src/server/accounts/app.ts:1642–1696,1820`). The API docs call out defaults: `reimportDeleted` true for backward compatibility, while file UI defaults false per current docs (`packages/docs/docs/api/reference.md:268–300`, `transactions/importing.md:46–58`).
- API exposes both `addTransactions` and `importTransactions`; raw add does not deduplicate, whereas import runs rules and reconciliation/dedupe (`packages/docs/docs/api/reference.md:253–300`). API docs say fuzzy matching should be reviewed when import IDs are absent. API docs include the model's split rules and merge constraints (`reference.md:175–212,324–333`).
- CSV export `packages/loot-core/src/server/transactions/export/export-to-csv.ts:7–15` prefixes strings beginning with `= + - @ tab CR` by apostrophe to mitigate spreadsheet formula injection. `exportQueryToCSV` includes split parent/child metadata, split ordering, categories, amount, cleared and reconciled labels (`69–141`). Note the source implements safety and data export; the exact user-facing export action is in desktop settings.

## Bank providers and constraints

- Provider overview: `packages/docs/docs/advanced/bank-sync.md:14–21` lists Akahu (NZ), Enable Banking (Europe), GoCardless BankAccountData (Europe; no new accounts per docs), SimpleFIN (North America), and Pluggy.ai (Brazil). The provider server implementations live under `packages/sync-server/src/app-{akahu,enablebanking,gocardless,pluggyai,simplefin}/`; client RPC registration is in `packages/loot-core/src/server/accounts/app.ts:1790–1821`.
- Sync docs: auto sync is off by default, only while Actual is open, minimum custom interval 15 minutes; any due linked account triggers a run for all linked accounts and manual/other-device syncs count toward the interval. Sync is skipped while server is unreachable (`packages/docs/docs/advanced/bank-sync.md:22–45`). Client stores per-device `bankSync.lastAutomaticRun` to avoid repeated immediate attempts (`packages/loot-core/src/types/prefs.ts:116–121`).
- SimpleFIN docs say at most 90 days of history and roughly once-daily upstream refresh (`packages/docs/docs/advanced/bank-sync/simplefin.md:78–83`). GoCardless sync start date is the later of oldest existing transaction and 89 days ago, i.e. a maximum 90-day request window inclusive (`packages/loot-core/src/server/accounts/sync.ts:75–103`). GoCardless docs note its BankAccountData signup was closed to new accounts as of July 2025 (`packages/docs/docs/advanced/bank-sync/gocardless.md:8–10`).
- Enable Banking and Akahu docs carry explicit experimental warnings and may require nightly (`packages/docs/docs/advanced/bank-sync/enable-banking.md:1–7`; `akahu.md:1–7`). Corresponding feature flags are `enableBanking` and `akahuBankSync` in `packages/loot-core/src/types/prefs.ts:1–15`. `packages/desktop-client/src/components/settings/Experimental.tsx:35–79` stores feature flags as synced preferences.
- Provider credentials and institution refresh cadence/coverage are third-party constraints, and should not be promised as uniform behavior. Local source was inspected, not exercised with external provider accounts.

## Privacy, sync recovery, backup and failure limits

- Docs describe local device plus selected-server storage, offline access and background sync (`packages/docs/docs/getting-started/sync.md:1–9`). E2EE encrypts budget data before sync but not local-at-rest data; forgotten E2EE password with no surviving local copy is unrecoverable; enabling encryption is one-way without backup/restore; sync reset may revert unsynced changes on other devices (`sync.md:17–68`). Avoid promising an account-password reset can decrypt E2EE data.
- Sync reset clears server sync state, uploads the chosen device's current data as authoritative, and creates a new sync ID; stale devices must revert to current cloud data (`sync.md:50–68`). User-facing errors and recovery messages are enumerated at `sync.md:70–98`.
- Manual export and restore are documented (`packages/docs/docs/backup-restore/backup.md:11–28`; `restore.md:3–38`). Automatic backups are desktop-only. Docs say up to 10 backups, with up to the most recent 15 minutes plus prior 10 used days (`restore.md:64–79`). The implementation groups by day, retains up to three current-day copies, one per other day, then latest 10 (`packages/loot-core/src/server/budgetfiles/backups.ts:81–104`). Database backups copy SQLite, remove CRDT message/clock tables from the archive and bundle DB plus metadata (`backups.ts:106–140`).
- Restore docs include a migration mismatch recovery procedure and recommend backing up before manual migration (`restore.md:40–62`). This is an operational edge case, not evidence that automatic repair always succeeds.
