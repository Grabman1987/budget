# Portfolio Performance ledger research

Inspected source: `portfolio-performance/portfolio`, commit `805c20dff5d999e987675181b4f1d82f81df10c0` (`master`, package version `0.89.1-SNAPSHOT`). The supplied official-site release reference is 0.89.0 as of 2026-10-15. Source claims in [portfolio-performance.csv](inventories/portfolio-performance.csv) point to GitHub files pinned to that commit. Rows PP-041–PP-075 use the canonical eleven columns, were written with Python `csv.DictWriter`, and were read back with `csv.DictReader`: 35 rows, exact header, sequential unique IDs, and 11 fields per record.

The repository’s `LICENSE` is Eclipse Public License 1.0. The project packages third-party libraries; the project license should not be treated as a blanket license for bundled dependencies. No upstream source was copied into the staging artifact.

The source model stores monetary amounts as scaled integer units, not an API that uniformly accepts cents: money precision is two decimal places, shares are eight, and quotes are eight. The quote-to-money factor follows the precision difference (10^6). Fees, taxes and foreign amounts are represented as transaction units; gross trade values are derived from net amounts and units. `Transaction.Unit.split(double)` rounds apportioned units and documents loss; `piece()` is available for reconciled allocation. Currency conversion and plan-generated share counts can therefore introduce rounding. Do not treat a PP internal amount as interchangeable with a cents-based integration field without an explicit conversion.

Cash and securities have separate transaction models. Account transfer entries insert two cash legs after validating both currencies; portfolio transfer entries represent two security legs. Delivery in/out covers position changes without an ordinary buy/sell. The model has a stock-split event and dividend payment events with ex-date/pay-date data. The event enum does not define spin-off or merger events. Representing those through deliveries is only an inferred manual path; this inspection did not establish cost-basis allocation or a dedicated wizard. Security type includes a `DEBT` value through legacy migration, but coupon accrual, bond maturity and redemption calculations were not established.

Investment plans can generate due transactions up to the current date. For a security purchase, generation requires a quote at each planned date, converts the net available amount when currencies differ, and rounds shares. Missing prices raise an IOException. The algorithm’s behavior does not establish that generated transactions are automatically created on a background schedule; callers/UI trigger generation.

CSV import is configurable and supports persisted mappings. PDF support is a collection of bank/document-specific extractors; it is not a general OCR claim. IB Flex XML import supports several statement date formats and pairs certain trade/tax rows. Import is review-oriented: only selected entries are applied; security overrides and note preferences are honored, after which consistency checks are scheduled. Duplicate detection marks potential duplicates; the inspected logic does not prove universal idempotency across formats. The IB Flex parser enables secure processing and disallows DOCTYPE declarations. Export has separate CSV paths for account transactions, portfolio transactions, security master data, quotes and merged prices; optional currency conversion applies to price exports.

Native persistence supports XML and protobuf payloads, compressed containers, and password-encrypted files. The encrypted reader reports password/signature/version errors; XML load runs model migration. The inspected encryption implementation uses AES/CBC and PBKDF2-HMAC-SHA1 with a fixed salt and an IV obtained from the initialized cipher for each save; this note records source behavior and is not a cryptographic assessment. It does not establish a cloud backup, automatic restore, transaction undo, or recovery from corrupted storage. Such recovery remains a user-managed procedure unless separately documented by product help.

Tests present in the pinned tree include `name.abuchen.portfolio.tests/src/name/abuchen/portfolio/model/{TransactionTest,PortfolioTransactionTest,InvestmentPlanTest,ClientFactoryTest}.java`, CSV account/portfolio/security/price extractor and exporter tests, `datatransfer/ibflex/IBFlexStatementExtractorTest.java`, PDF assistant tests, and UI import-controller coverage. These files were inspected as coverage indicators only; no tests or upstream code were executed. Cases still worth checking in a product-specific acceptance suite include fractional share split rounding, cross-currency fee/tax reconciliation, transfer legs across currencies, plan generation around holidays/time zones and missing quotes, repeat-import identity outside plan items, spin-off/merger basis allocation, scanned/changed broker PDFs, IB Flex timezone interpretation, CSV escaping and locale variation, corrupted encrypted/compressed files, and large-client export/migration behavior.
