# Toolkit 3.23.0 functional notes (P2b)

Read-only review of commit `631c914714e747e0b4478e3ac521057761622bcd`, package `toolkit-for-ynab` version 3.23.0. Findings below describe inspected source and checked-in tests; tests/builds were not run and upstream code was not executed.

## Algorithms and behavior

- **Days of Buffering** (`src/extension/features/budget/days-of-buffering/index.js`): `lookbackDays` parses the selected month count and multiplies by 30; “all” becomes zero/unlimited (10–12). Eligible transactions are accepted, non-tombstoned, non-internal-payee, non-transfer, on-budget account outflows with negative amount; a finite window uses `transaction.date.daysApart(today) < lookbackDays` (163–181). Available balance sums non-tombstoned account-calculation balances across on-budget accounts; optional credit-card exclusion filters `accountType === 'CreditCard'` (27–49). It computes `totalOutflow` as the sum of negative signed amounts, `averageDailyOutflow = abs(totalOutflow / availableDates)`, then `balance / averageDailyOutflow`; under 10 days displays one decimal, otherwise floors (121–160). Actual `availableDates` is the day difference between the latest and earliest eligible transaction, capped by the configured 30-day-month window (133–140), not a fixed divisor equal to selected days. It checks at least 15 unique eligible transaction dates, but does not require 15 full days of elapsed history (149–152). Zero date span or no outflow has no explicit denominator guard. Date-of-buffering tooltip adds that displayed value to “today” (189–196). Settings document options 1/3/6/12 months and all history and warn excluding credit-card accounts inflates the estimate (`settings.js:1–26`). No feature-specific test file was found.

- **Pacing** (`src/extension/utils/pacing.js`): only the current budget month is shown by feature code (`features/budget/pacing/index.js:18–31`). For a budget display item, `budgetedPace = -activity / balancePriorToSpending`; `monthPace = today.dayOfMonth / daysInMonth`, overridden to 1 for past months and 0 for future months; `paceAmount = round(balancePriorToSpending * monthPace + activity)`; `daysOffTarget = 0` for a zero pre-spend balance, else `round(today.dayOfMonth - budgetedPace * daysInMonth)` (pacing.js:16–72). Transactions for tooltip count are category parent transactions and split subtransactions dated in the current month only (47–57). UI settings show currency amount, indicator or ahead/behind days (`features/budget/pacing/settings.js:1–13`; rendering `features/budget/pacing/index.js:134–185`). It persists a per-budget-version list of deemphasized category IDs (pacing.js:4–14). No pacing test file was found.

- **Date of Money** (`src/extension/features/budget/date-of-money/index.js:23–37`): reads YNAB's current-month `budgetViewModel.monthlyBudgetCalculationForCurrentMonth.ageOfMoney`, subtracts that integer from YNAB's “today”, and formats using YNAB's date formatter. This is a displayed date derived from the host-calculated AoM; Toolkit does not independently calculate FIFO income age. No feature-specific test file was found.

- **Custom Average Budgeting** (`src/extension/features/budget/custom-average-budgeting/index.tsx:42–102`): start month is local JS current date minus configured 3/6/12 months, normalized to first of that month; end month is prior month normalized to first (`settings.js:1–15`). Fetches selected category's ordinary transactions and split subtransactions separately, includes non-tombstoned matching category rows for `isBetweenMonths(startMonth,endMonth)`, sums signed `amount`s, and tracks distinct month keys only for rows found. It returns absolute sum divided by count of distinct months with at least one matching transaction, not by configured lookback months; zero sum returns zero. Thus empty months do not dilute the average, and all signed activity within those months contributes. Only exactly one selected category is supported (104–110); click assigns the returned value to that category's `budgeted` field (112–121). No dedicated test found.

- **Paid-in-full credit-card assist** (`src/extension/features/budget/check-credit-balances/index.js`): current budget month and budget page only (`15–17`). On debt-payment categories, mismatch is `-available` if account balance is positive; otherwise `-(available + balance)` (`138–142`). Nonzero mismatch gets yellow-highlight attribute and account-nav ≠ marker (98–129). For one selected credit-card payment category, the inspector button displays mismatch and changes category budgeted amount to `budgeted + difference` through YNAB's currency input/change/blur path; it is not a direct ledger transaction (`50–96`). No dedicated test found. UI setting is documented at `settings.js:1–9`.

- **Reports: shared filters and transaction sets.** `toolkit-reports/common/components/report-context/reports-provider.tsx:32–106` defines nine report tabs and whether each supports category filters or tracking accounts. Base reportable transaction rows exclude split parents and scheduled parent/subtransaction rows while keeping scheduled rows separately (`153–180`). Account and category filters filter included IDs, and transaction date boundaries are inclusive (`309–337`). Date picker/filter components are in `pages/root/components/report-filters/`; account, category, date and optional report-specific filters are user-visible. README lists tab names and `#toolkit-reports/{net-worth,inflow-outflow,spending-by-category,spending-by-payee,income-vs-expense,income-breakdown,balance-over-time,outflow-over-time,forecast}` routes (`features/toolkit-reports/README.md:18–38`).

- **Balance Over Time.** `pages/balance-over-time/utils.ts:41–67,114–171` sorts all reportable transactions, creates daily UTC datapoints from earliest transaction through current UTC day, and tracks per-account running balance from zero by adding inflow minus outflow. Missing days carry the prior total; selected date filters are inclusive (`236–248`). Accounts may be separated or combined by account type / selected accounts; step graph defaults on and trendline defaults off (`BalanceOverTime.tsx:43–57,92–158`). Dataset is capped at 20,000 points (`utils.ts:7–10,254–256`). Optional schedule projection runs through today + 12 calendar months; recurrence mapping includes daily through every-other-year and “twice a month” modeled as 15 days (`259–310`). Occurrences strictly after the last actual datapoint and through the projection horizon are included; split subtransactions are excluded because parent recurrence carries aggregate amount (`282–310,327–389`). Existing specs cover never/monthly/weekly boundaries, account isolation, carry-forward and projection amounts (`utils.spec.ts:29–110`); not the base daily-map utility as comprehensively.

- **Net Worth.** `pages/net-worth/component.tsx:200–321` sorts all reportable transactions (including outside the selected date range), maintains account cumulative signed balances month over month; positive account totals are assets, negative totals become positive debt magnitudes, net worth = assets − debts, debt ratio = debts/assets × 100 (216–232). Account filter excludes selected accounts; date range slices month labels after lifetime cumulative calculation (247–257,267–300). Category filter is disabled for this report per provider settings. Empty months are inserted and carry previous monthly totals (267–285). “Flip Debt” only changes chart sign rendering, with preference persisted (103–110,166–193). No net-worth component-specific test found.

- **Inflow/Outflow.** `pages/inflow-outflow/component.tsx:164–296` groups by transaction month/account; on-budget transfers are omitted; signed positive amounts are inflows and negative amounts are outflows. Month difference = inflow + signed outflow. Savings fraction is `1 - abs(outflow)/inflow` when inflow >= spend, otherwise zero (267–275). Empty months are inserted and date filter slices displayed months. This report has an existing context filter for category and account. No direct component test found.

- **Outflow Over Time.** `pages/outflow-over-time/utils.ts:20–64` selects outflow-only rows by default; optionally includes inflows except “Inflow: Ready to Assign”. Transfers count only if transfer counterpart account is outside the included account set. Date bounds are inclusive, transaction groups are monthly/day-of-UTC, and cumulative values run through calendar days. Forecast uses last N calendar days of each historical month aligned from month end to each remaining day of this month; average denominator is months with any transaction, with zeroes included for missing dates inside those months and months with no transactions skipped (159–201). Tests include grouping, arithmetic, account filtering and these forecast edge cases/examples, including leap February and empty-month handling (`utils.test.js:11–35,37–130,239–331`).

- **Forecast.** `pages/forecast/functions.ts:15–70` derives weekly net cash changes from filtered transaction weeks (excluding payee `Starting Balance`), creates 100 paths, each 520 weeks long by random resampling weeks with replacement, and sorts paths by final value descending. Initial net worth sums all reportable transactions excluding selected accounts, not just the date/category-filtered subset (57–69). Weeks with no transactions between first and last observed transaction week count as zero; no weeks outside that observed span are sampled. Specs inject deterministic random selection and cover path length, inflow/outflow, sampling and zero weeks (`functions.spec.js:25–129`).

- **Register bulk actions / search controls.** Bulk memo action operates on YNAB's checked account rows in one `performAsSingleChangeSet`; supports replace, add prefix, add suffix (`features/accounts/bulk-edit-memo/index.jsx:21–47,151–176`). Bulk date action likewise updates each checked transaction's YNAB `date` in one change set (`bulk-edit-date/index.tsx:13–37,89–117`). Both inject into a specific register action-bar selector and locate the built-in “Categorize” row. Bulk payee option calls YNAB account service `openPayeeModal()` (`bulk-manage-payees/index.js:5–45`). No bespoke transaction-search algorithm found: Toolkit adds one-click toggles for host scheduled and reconciled filter fields by setting `filters.propertiesToSet[field]` and calling `applyFilters()` (`toggle-transaction-filters/index.tsx:7–37,61–74`); this makes the host's built-in register search/filter controls the primary search behavior. Cleared/flagged feature only changes the order of two DOM columns (`swap-cleared-flagged/index.js:12–51`); it does not change transaction status/flag values.

- **Clipboard and printing.** Category Activity Copy maps selected activity rows into Account, Date, Payee, Category, Memo, Amount; split-row payee is resolved from its parent transaction. It uses YNAB localized date/currency formatting and writes tab-separated records with CRLF to clipboard (`features/general/category-activity-copy/copyTransactionsToClipboard.ts:13–41`). Despite the local variable name `csv`, delimiter is tab; no CSV file export. Printing Improvements is CSS under `@media print`, hiding navigation/inspector and reflowing budget UI (`features/general/printing-improvements/index.css:1–23,43–95`); no custom PDF/export implementation.

## Tests and implementation limits

Checked-in relevant specs: `toolkit-reports/pages/balance-over-time/utils.spec.ts` (scheduled projection), `outflow-over-time/utils.test.js`, `income-vs-expense/normalizer.test.ts`, `forecast/functions.spec.js`, plus `toolkit-reports/index.test.js` and `utils/url-navigation.test.ts`. `normalizer.test.ts` still has TODOs for same-month combining and summing at lines 85–89; other cases exercise missing-month combinations. There are no feature-specific tests in the days-of-buffering, pacing, date-of-money, custom-average-budgeting, check-credit-balances, printing, bulk memo/date/payee or toggle filters feature directories. This is a file-based inventory, not a test run.

The implementation is a browser extension tightly bound to YNAB’s private app runtime: global `ynab.YNABSharedLib.defaultInstance.entityManager`, `YNAB.NAMESPACES[0].__container__`, Ember service/controller lookup, YNAB custom date/currency helpers, private view models, React component rendering hooks, and CSS/DOM selectors. Representative references: `src/extension/utils/ynab.ts:8–10,46–89`, `src/extension/utils/ember.ts:4–48`, `features/accounts/bulk-edit-memo/index.jsx:33–47,156–176`. The formulas may be transferable, but the original calls, types and injected UI require host-specific adapters and are susceptible to YNAB internal changes.
