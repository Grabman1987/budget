## Already usable when trusted evidence is injected

- `StrategyEvidenceProvider` in `apps/server/src/api/portfolio-strategy.ts` is a server-only `(asOf) => Promise<StrategyEvidence>` seam. `createLedgerApi` in `apps/server/src/api/index.ts` already accepts `strategyEvidence` and passes the same provider to authenticated strategy GET/manual monthly POST. HTTP bodies cannot assert `verified`.
- `apps/server/src/strategy/monthly-evaluation.ts` exports `evaluateStrategyMonthOnce(db, provider, now)`. It asks the provider for evidence, verifies UTC day did not change while awaiting it, checks the verified month window, then calls the transactionally guarded automatic writer. That writer requires the month setting absent **and** month audit count zero, so Undo cannot cause automatic resurrection. Its default unavailable provider writes nothing. This is an exported one-shot service, not a scheduled operation.
- The domain trend reader requires a caller-attested complete ordered US-session list, actual UTC completion instants, 220 matching positive close observations, consistent source/index identity, and observation timestamps no later than `asOf`. It checks internal consistency; it cannot prove an external feed's market identity or calendar completeness by itself. Existing saved decisions retain and replay their original 220-session/close facts.
- `AppOptions.ledger` in `apps/server/src/app.ts` does **not** expose `strategyEvidence`; its spread to `createLedgerApi` would carry it once typed. `apps/server/src/index.ts` constructs no strategy provider and calls no strategy evaluator. `startDailyMarketTimer` is opt-in for ordinary instrument prices/ECB/CPI and a crypto read source; those generic `MarketSources` operate on security identifiers, including fallback Yahoo, and do not provide an attested unlevered NDX USD series or complete US sessions. `startPlanSnapshotTimer` is unrelated.

## External evidence and operational dependencies, not new owner policy

1. The [Nasdaq NDX identity](https://indexes.nasdaq.com/Index/Overview/NDX) and [FRED NASDAQ100 series](https://fred.stlouisfed.org/series/NASDAQ100) are documented candidates, but the exact FRED-series-to-unlevered-USD-*price-return*-NDX crosswalk and representative close still need verification against an authoritative Nasdaq observation before code may emit `verifiedIndex: 'nasdaq-100-usd-price-index'`. FRED's supported observations API needs a server-side key; no key is configured or accessed here. Permitted automated use and any Nasdaq redistribution restriction must be established for the deployment. The existing EUR Nasdaq ETF benchmark, a user security price, and Yahoo `^NDX` alone are not that proof.
2. The official [Nasdaq Trader US trading calendar](https://www.nasdaqtrader.com/trader.aspx?id=Calendar), prior annual calendars and applicable early-close/exception alerts can support a **bounded reviewed manifest** with session dates, actual Eastern close times converted to UTC and a recorded covered interval/version/source. No such reviewed manifest or proven complete machine-readable actual-session feed exists in the repository. Weekdays minus holidays and gaps in FRED closes cannot certify unscheduled closures or early closes. `verifiedComplete: true` therefore cannot currently be emitted honestly.
3. The close feed must be available after the verified penultimate US session closes and within the existing monthly writer's signal-date through last-session-date window. FRED's observation date is not a publication timestamp. `observedAt` can truthfully be the server's retrieval time; `closedAt` needs the verified session close instant. Timeliness inside that window is unproven. If a source arrives after it, the current writer correctly skips; this assessment does not add backdating or catch-up policy.
4. Broker/exchange execution calendar evidence is separate and optional under the owner's decision. Keep the broker-independent nominal 15th provisional when absent; the US index signal calendar cannot certify the actual sparplan execution day.

The earlier provider research could not inspect live FRED/Nasdaq responses because direct requests were blocked by CONNECT 403. This assessment does not repeat those downloads or turn public page descriptions into verified runtime evidence. A key, reviewed mapping and actual-session manifest/process are external evidence/operations dependencies, not an unasked owner product decision.

## Smallest honest next source package

The only credential-independent composition delta available immediately is adding `strategyEvidence?: StrategyEvidenceProvider` to `AppOptions.ledger` and forwarding the **same explicitly supplied provider** through `createApp` to the already existing API seam. The spread currently handles runtime forwarding; the type omits the property. This would make injection usable by a host that already possesses verified evidence, but it does not supply evidence to the shipped `index.ts`, refresh the daily signal or make automatic operation live. It is a narrow integration-enabler, not a delivery slice by itself.

An actually useful provider/scheduler source package must follow the external evidence contract above: (a) a fixed-identity bounded close adapter, e.g. FRED's documented observations API with a configured key, exact decimal-to-integer parsing, explicit source/version and no secret/raw-response logging; (b) an independently reviewed complete US-session manifest or authoritative equivalent, including exceptional closures and early closes, with coverage/revision/fail-closed expiry; (c) one composed provider shared by API and monthly evaluator; (d) a provider-gated scheduler that checks only when the verified penultimate/last-session window can be served, respects held writes and bounded retries, and registers a shutdown stop before DB close. This package must not use a current-price row as an index observation, infer sessions from weekdays or quote gaps, assert `verified` without the external checks, issue broker orders, or reuse the generic nightly market timer's 02:30 Vienna policy as the index decision clock. Existing UTC day and absent-plus-audit writer fences remain intact. Source review would be independent and runtime/provider acceptance would remain unclaimed.

**Recommendation:** implement the tiny `AppOptions` provider passthrough only if a real verified provider is being supplied by another trusted host in this source slice. Otherwise keep the default unavailable and defer scheduler activation until the fixed index identity, usable access and bounded official calendar are supplied. Adding an unavailable-provider timer or a stub that never emits verified evidence would not close the accepted daily/monthly automation gap. No source implementation was authorized or made in this assessment. #762 remains **NOT VALIDATED / NOT LIVE**.
