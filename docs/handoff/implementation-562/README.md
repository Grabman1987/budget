# Bank review list preparation (#562)

This branch adds read-only suggestion labels to the inbox list response. It reuses the existing guarded candidate match and assignment-rule readers, after the API applies source, period and page selection. One eligible merge is shown first, then one available rule. A single transfer is labelled as a distinct counterpart; competing matches/rules and failed preparation say “Vorschlag prüfen”. A manual rule is explicitly labelled for selection because the existing popup does not preselect it. The existing category fallback remains “Zu verteilen” and requires review. The UI shows the prepared choice on each row without opening it. “Übernehmen” continues to open the shared booking dialog; only its existing explicit action writes. “Nicht übernehmen”, bulk actions, confirmation, audit, locks, cents and Undo code are unchanged.

The global/source Prüfen response reports progress from open reviewable candidate rows, the existing canonical unclassified-booking predicate, and linked booking history. The embedded account list deliberately contains only candidate rows, so it does not render or return this progress. Generic foreign-currency tasks are excluded. A linked booking remains open while that canonical task is open, regardless of pending/confirmed status; an extant linked booking without that task counts as reviewed. A direct link to an existing classified manual or migrated booking counts as reviewed. Unknown or deleted linked targets are not claimed as reviewed. Dismissal counts as reviewed. Existing Undo changes these projections without new persistence. This is a cumulative count, because the data model has no weekly review batch identity. A new category prediction beyond existing assignment rules would need a product policy; none was inferred.
