## Scope and data contract

- Four exact successful primary GET payloads enter `budget-offline-views` IndexedDB: `/api/heute?period=…&month=…`, unfiltered `/api/accounts`, the current-month `/api/budget/YYYY-MM`, and the first default latest-bookings page (`to` plus `limit=50`, no filters/cursor). Request path, timestamp, session generation and original integer-cent response are stored. No auth result, headers, credentials, other page, historic Plan or filtered bookings are stored. Failed GETs leave the prior successful row unchanged. A blocked device-store open cannot indefinitely delay an online read; after 500 ms that response is delivered live without snapshotting.
- The offline surface has read-only Heute values and their available/open source rows, every account's native balance and explicit unknown EUR flag, current-month Plan totals and category rows, and latest bookings in server order. Each carries `Stand vom <Datum Uhrzeit>` from its own completed fetch. Plan rejects a saved prior month's key after month rollover. No dependent live queries are mixed into these rows and no missing valuation is calculated.
- Live routes stay mounted but hidden and inert after an in-session disconnect, retaining unsaved form fields. The shared request boundary rejects offline writes except the existing idempotent queued booking capture path. Cold offline starts mount only the static surface and queue capture. Other paths retain an offline notice with no financial view.
- Sign-out and session-expiry cleanup revoke snapshots in every open tab. A temporary, nonfinancial `budget-offline-wipe-pending` marker blocks read and write after a delayed database open or a three-second cleanup timeout. An atomic transaction changes the IndexedDB epoch and physically clears view rows; only its completion removes the marker. A blocked clear leaves physical deletion unconfirmed and the marker in place; the next snapshot read attempts that wipe again while remaining blank. Unsent text bookings retain #557 behavior.
