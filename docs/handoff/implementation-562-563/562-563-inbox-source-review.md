## Findings

1. **P2 — A link-only/protected candidate is offered as a ready merge.** `packages/db/src/repos/inbox-bank-suggestions.ts:92-109` combines `candidateMatches(...).merge` and `.link` into `alternatives`, then marks the sole exact-date/simple target `ready` with action `merge` and a “zusammenführen” label. The existing `candidateMatches` explicitly defines `.link` as bookings that cannot take over the bank date (migrated or locked), at `packages/db/src/repos/bank-followups.ts:204-217`. `mergeBankCandidate` at lines 283-290 catches a non-adoptable target and *links* it instead. Thus a single link-only target satisfying the lightweight simple/date/amount filters can be accepted by “Passt ✓” or the batch and the audited result is a reference link, not the promised merge; a protected/manual-decision path crosses the safe shortcut. Keep `.link` candidates under individual review and build ready merges only from `.merge`. Retain the existing writer's manual fallback for its original routes.

2. **P2 — A post-commit refresh failure reports a failed acceptance and hides its Undo.** Both the batch and dismissal handlers use `write(...).then(result => result ? reviewed(...) : setFailed(true))` at `apps/web/src/inbox/bank-suggestion-review.tsx:69-92`. The inherited `useBudgetWrite` awaits `refresh()` *after* `run()` succeeds and before showing the Undo toast or returning the result (`apps/web/src/budget/use-category-writes.ts:50-84`). If any unrelated invalidated query rejects, that catch returns `undefined`: the server may already have committed one audit group, but the new UI says “Die Vorschläge wurden nicht übernommen”, leaves progress unacknowledged, and offers no group Undo. Reconcile committed success separately from refresh failure and preserve the committed group receipt/Undo path; a later list refresh can report its own error. The stale revision checks should prevent a duplicate write on retry, but they do not fix the false outcome or lost Undo control.
