## Findings

1. **P2 — Undo of a reassessment leaves the adopted document facts stale.** `apps/web/src/statement-intake/statement-settlement-727.tsx:562-570` adopts the revised source into both the settlement component and parent. The reassessment group includes the source `reopen`/`review` writes (`packages/db/src/repos/statement-settlement.ts:384-399`), so Undo restores the prior reviewed source. Both the inline Undo at `statement-settlement-727.tsx:645-663` and the Undo toast in `apps/web/src/budget/use-category-writes.ts:62-80` only invalidate the generic query set (`use-category-writes.ts:14-26`); neither fetches/adopts the reverted statement intake. Reproduction by source logic: reassess a represented bonus with a changed payable or date, then click either Undo. The parent document review continues to display the reassessed facts and retains that revision in its local `current`/`saved` state, despite the server having reverted them; returning to the settlement pane carries the stale source until the user manually chooses “Stand neu laden.” The parent also has no conflict flag set by this Undo. Minimal fix: after successful Undo of a source-review group, fetch that intake and call `onSourceAdopt` (and update local source/captured state), or explicitly force an immediate document reload before showing/editing the parent view. Preserve the current CAS refusal on any failed reload.

2. **P3 — The represented-bonus Undo label describes a different action after reassessment.** The new path makes `bonus.actionGroupId` the *reassessment* group (`packages/db/src/repos/statement-settlement.ts:400-411`). The existing button at `apps/web/src/statement-intake/statement-settlement-727.tsx:1446-1455` then says “Gutschriftzuordnung aufheben” because the reassessment writer sets `representationKind: 'linked'`, even for an originally created credit. `undo(bonus.actionGroupId)` actually reverses the source reassessment and restores the previous represented bonus; it does not detach or delete the credit. The incorrect promise is visible immediately after saving any reassessment. Use a neutral last-action Undo label, or expose the action kind to label a source-review Undo accurately.
