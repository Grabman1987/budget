## Finding

**P2 — Successful selected funding can be reported as not applied and lose its Undo offer after a refresh failure.** `apps/web/src/budget/selected-funding.tsx:50-57` treats any `undefined` from `useBudgetWrite` as a failed apply and displays “Änderungen wurden nicht übernommen.” The shared writer first awaits the server action and then awaits query invalidation; it catches a rejection from either step and returns `undefined` (`apps/web/src/budget/use-category-writes.ts:50-56,62-85`). Thus when `/funding-apply` commits its grouped assignment but an active query refetch rejects, the dialog says the changes were not applied, clears the single-use preview, and the Undo toast at lines 62-80 is never offered. The server ticket was consumed and `assignMany` has already written (`packages/db/src/repos/selected-funding.ts:95-107`). Minimal fix: distinguish confirmed write success from follow-up refresh failure in the writer/caller contract, show a neutral refresh error with the committed action's Undo handle, and avoid the false “not applied” claim. The same shared-writer limitation also affects the new snooze caller's success feedback, though it has no false-not-applied text.
