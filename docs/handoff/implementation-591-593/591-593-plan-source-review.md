## Findings

1. **P2 — “Sichtbare” quick actions include category rows hidden by a collapsed group.** `apps/web/src/budget/plan-page.tsx:534-547` builds the new inspector's `actionIds` from every row in `groups`/`visibleMultiGroups`, without consulting the existing `collapsed` set. The table at lines 1018 and 1114-1116 omits those rows when a group is collapsed. For example, collapse a group containing the only funded category, leave no selection, then click “Auf 0 zurücksetzen”: the inspector says one visible category and resets a row that is absent from the visible table. This violates #592's no-selection scope and can move money unexpectedly, though the server still applies its canonical guards and Undo. Filter the unselected inspector action IDs by groups whose rows are rendered; preserve explicitly selected rows according to the agreed selection behavior. Keep preview and POST ID order identical.

2. **P2 — The new month status can say nothing is underfunded while a hidden category has an unmet target.** `MonthOverview` obtains canonical figures from `data.summary.envelopes` (`apps/web/src/budget/plan-page.tsx:1445-1447`), but calls `monthStatus(summary, rows)` with `rows = planRows(data)`. `planRows` excludes hidden categories with zero available and activity at `apps/web/src/budget/plan-model.ts:94-102`; the new underfunded count at lines 636-638 therefore misses a hidden category with positive `needCents`, target and zero current balance/activity. In that concrete state the status is “Nichts ist unterfinanziert oder überzogen”, while the same canonical summary still contains unmet target need. Count the no-selection month status from canonical envelopes, as the adjacent month arithmetic already does; keep filtered/visible scopes only for the quick actions.

3. **P2 — A failed refetch with cached data leaves the new exact-preview actions enabled.** `PlanMonthPage` shows `ErrorNote` for `budget.isError` but still supplies retained `budget.data?.months` to `PlanBody` (`apps/web/src/budget/plan-page.tsx:138-183`). `panelReady` at lines 468-475 checks only that cached record's month matches; `inspectorActionRows` and `PlanInspector.sourceUnavailable` at lines 542 and 1165-1174 therefore treat a failed refresh as current data. If assignments changed elsewhere before the failed refresh, the displayed quick delta or one-click cover can differ from the server's fresh write. The old generic forms had no CAS either, but #592's new exact click-preview and #593's direct amount button add a false exactness claim. Preserve the captured view and draft on error, while disabling these inspector money shortcuts until a successful bounded read returns. No financial formula change is needed.
