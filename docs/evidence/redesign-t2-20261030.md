## Contract and implementation

`GET /api/heute` adds `forecast35d`, copied from exactly one existing
`liquidityReportView(db, day, { horizon: '35d', levers: [] })` call. Its only fields
are source `asOf`, horizon, empty levers and the existing availability result; the
report contains only `startDay`, `startCents`, `horizon`, `horizonDays`, `points`,
`eventMarks`, `low`, `scheduledInflows`. Known missing valuation inputs use the
existing `availableSection` handling. No second formula, ledger revision identifier,
six-month verdict, movement detail, event-management list or income-pause list is added.

The final route preserves the original plain-database Heute/provenance/other-reader
calls. An initial whole-route transaction was removed after source review of
`request-memo.ts`: transaction handles cannot populate fresh memo entries. No memo
implementation, cache flag, prewarm or double read is introduced. No new cross-metric
SQL isolation or measured performance equivalence is claimed.

With the redesign build flag ON, the compact card reads the new field directly;
the unchanged existing Heute HTTP response is what the approved snapshot store saves.
Offline renders that same field with its source date and the existing response
`fetchedAt`/permission epoch. The epoch remains an authorisation boundary, not a
financial ledger revision. OFF retains the independent canonical 35-day query and
the existing offline budget-window presentation. If the aggregate read fails, the
live ON card can use that same independent canonical 35-day query. A successful older
response with no new field stays unavailable; it never substitutes `balance.low` or 0.

While the aggregate is pending/refetching, supplied older card data is withheld.
The separate payday/month budget projection remains available with a distinct label
under ON. The chart and salary-selector changes narrow accepted TypeScript fields
only; their runtime calculations are unchanged. Generic HTTP persistence, approved
snapshot keys, permission epochs, expiry/logout/clear logic, database calculations,
financial writers, router/report-search/report-page code and generated styles are unchanged.
