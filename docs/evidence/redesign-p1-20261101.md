## Pre-existing concurrency boundary

`budget-api.ts` `assign()` sends absolute assignment cents without an expected
revision. The unchanged target-preview `take()` in `plan-page.tsx` uses that
writer. `apps/server/src/api/budget.ts` forwards to `assignMany`; the repository
`packages/db/src/repos/budget.ts` re-reads current funding inside the transaction
but applies supplied absolute cents. The existing atomic `quickAssignMany`
empty-fill path instead re-reads its categories and cannot overwrite a row that
has since become nonempty (existing API regression in `budget.test.ts`).

These are distinct guarantees. Universal stale-preview rejection is not proven
by the existing absolute writer and is not claimed here. Root is examining the
complete existing guard path separately. P1 adds no UI-only fresh-read guard,
revision protocol, server/financial policy or misleading atomicity guarantee.
