# S1: fail-closed frontend build flag

Refs #822. Implementation base: `0acbcd284f9ab0fd74fef707e4be4be965762f7d`
(the locally verified T1 reference contract, stacked on T0).

## Scope

One frontend constant, `REDESIGN_ENABLED`, reads only the compile-time
`VITE_BUDGET_REDESIGN` value and is true only for exact `1`. No query, localStorage,
profile, service or backend decision selects it. The existing `.app` element gains
`data-budget-redesign="1"` only when enabled. Existing layouts, routes, financial
rules, controls, generated styles and authentication are unchanged.

The Docker base build explicitly selects `0`; the existing preview rebuild selects
both `VITE_BUDGET_PREVIEW=1` and `VITE_BUDGET_REDESIGN=1`. Public targets and the
final default production target are retained. A later production activation still
requires its separately approved build-input change and current-main release.

The existing full visual CI job runs the bounded build/browser smoke. The existing
Docker job additionally compiles the preview target, without pushing or deploying.
No job condition, required aggregate, timeout, branch guard, release helper,
credential or Fly configuration is changed.

**Future S2/S3 scope obligation:** `.app` does not contain `TabBar`, `PanelHost` or
the shell's live announcement. Future styling must deliberately isolate these
surfaces too, including portals; the attribute is not permission for global CSS.
S1 does not move or restyle them and does not claim redesigned area acceptance.

## Test rationale and observed red/green

- `redesign-flag.test.ts` checks eight literal inputs via fresh module imports.
  The initial OFF implementation failed only the exact `1` case (**one failed,
  seven passed**); the strict equality implementation passed all eight. This
  catches unsafe truthiness/coercion as well as an always-OFF flag.
- `scripts/dev/redesign-smoke.ts` builds real production OFF/ON frontend artifacts
  into its own temporary directory. It starts the unchanged server with a fresh
  synthetic SQLite database, real test passkey/session bootstrap, disabled external
  integrations and a non-production pinned date. No hosted session or private data
  is used. The health revision identifies the owned local server before bootstrap.
- Before wiring the shell attribute, that smoke reached the real ON build after
  explicit service-worker update consent and failed on the missing root attribute
  at the ordinary **5,000 ms** assertion timeout. After wiring, both **1440 px
  desktop and 390 px mobile** passed OFF → ON → OFF artifact upgrades.
- On both viewports, URL/localStorage activation attempts leave OFF disabled.
  The actual existing inbox body, period selector, main heading and title render;
  the preview marker follows the build. The same origin, authenticated session and
  `/konten/pruefen?von=%2Fkonten` bookmark remain usable before and after updates.
  Waiting workers leave the current shell active until consent. Old hashed assets
  remain served while the new artifact tree is merged into the disposable web dir.
- Existing flag/date/release-target/CI-plan/PWA unit checks: **five files,
  81 tests passed**, serialized with one worker.
