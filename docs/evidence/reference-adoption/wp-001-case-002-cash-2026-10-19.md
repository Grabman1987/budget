## Independent literal oracle

One on-budget checking account opens on 2023-10-01 with 100,000 cents. One empty
expense category has no assignments in October or November. A confirmed expense
of 2,500 cents is posted on October 31. No card, transfer, income, hold or further
booking exists.

| Observed state | Account cash | Category available | Free funds | Uncovered reset |
| --- | ---: | ---: | ---: | ---: |
| Before spending | 100,000 | 0 | 100,000 | 0 |
| October after spending, either mode | 97,500 | −2,500 | 100,000 | 0 |
| November, carry disabled | 97,500 | 0 | 97,500 | 2,500 |
| November, carry enabled | 97,500 | −2,500 | 100,000 | 0 |
| After expense undo, both months | 100,000 | 0 | 100,000 | 0 |

The expense consumes 2,500 actual cash cents. In October the negative envelope
represents the still-uncovered obligation, so free funds have not yet been reduced.
At rollover, disabled carry clears that obligation from the envelope and reduces
free funds by 2,500 once. Enabled carry retains the negative 2,500 in the envelope
and must not also subtract it from free funds. Rollover itself never posts another
account mutation. November assignment and activity are independently asserted zero;
cash overspending and credit overspending remain distinguished. Expected amounts
are literal constants, not values obtained from production calculators.

Undo is exercised after both months were read, so stale carry and funding-pool
results are observable. Repository tests restore the entire initial queried state;
API tests assert literal initial financial state for both October and November.
Authentication uses the established signed-in test gate and is not new auth proof.
