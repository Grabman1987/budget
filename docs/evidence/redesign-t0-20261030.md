## Diagnosis

Scheduled main run `41028177749` failed in `e2e(6)`; the preceding scheduled
run `40842964335` passed at the same revision. The failing browser had already
reached `/konten/pruefen?von=%2Fkonten`. Its initial inbox request used
`segment=auto`; the successful response selected `aufgaben` with zero transactions
and four account tasks. The visible destination was the task-source overview.
`Offene Entscheidungen` belongs to the transaction body or a selected task-source
drilldown, so asserting it unconditionally depended on shared ledger contents.

This is a test fixture/contract defect. Production routing and automatic segment
selection remain unchanged. No private logs or financial records are included.

## Scoped change and coverage

`e2e/inbox.spec.ts`: replace the shared-state assumption with two complete,
typed synthetic row fixtures, using the existing API fixture helper with optional
segment/source metadata and required paginated summary fields. Both cases exercise
the actual router and rendered components. They check the destination path,
`von=/konten`, absence of the old modal, initial `auto` request and pagination,
selected segment, destination heading and concrete row content. The tasks case
also checks its source table and opens the real source drilldown before checking
the retained `Offene Entscheidungen` heading.

These checks catch a broken redirect, lost return origin, hardcoded initial
segment, missing destination body, or missing fixture row. API mocks isolate
the redirect test from unrelated shared-ledger writes; existing real-database
API tests retain responsibility for server segment selection. All other inbox
test assertions, timeouts, retries, skips and financial expectations are unchanged.

`docs/evidence/redesign-t0-20261030.md`: records only synthetic diagnosis and
verification. No product, visual, database, authentication or deployment change.
