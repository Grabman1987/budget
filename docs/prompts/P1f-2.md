# P1f-2 — Auth and backup hardening

Paste into a new cloud session after P1f-1 PR 1 is merged (model: Opus recommended — security). B1–B3 before the first deploy; B5 before any real data.

---

Read `CLAUDE.md`, `SPEC.md` §9, `docs/ops.md`, `docs/audit/2026-09-29-p1-audit.md` section B and the P1f-2 checklist in `docs/ROADMAP.md`.

Task: fix findings B1–B7 on a fresh branch `p1f-2-auth` from `main`. One PR of at most ~1.500 changed lines; if B5 does not fit, open it as a second PR `p1f-2b-backup`.

1. **B1** Origin-guard and other unauthenticated rejections: rate-limit and deduplicate before writing `auth_event` (e.g. one row per kind and ip-hash per 10 min with a counter), truncate every `detail` to 100 characters, prune `auth_event` older than 180 days on start and daily. Test: 10.000 rejected requests produce a bounded number of rows.
2. **B2** Revoke recovery-code sessions on `recovery/regenerate` and on passkey revocation; add a step-up-protected endpoint "Alle anderen Sitzungen beenden" and a button in Einstellungen › Sicherheit; fix `docs/ops.md` §7/§9.
3. **B3** `bodyLimit` 64 KB on `/api/*`, registered before the origin guard; 413 with a plain message.
4. **B4** Recovery codes: HMAC-SHA-256 with a server pepper from secret `BUDGET_PEPPER` (required in production, generated per run in dev/test) or scrypt; ≥ 80-bit codes, readable groups. Migration path: existing hashes invalid → owner regenerates after deploy (note in PR description).
5. **B5** Client-side encrypted backup: nightly job (in-process scheduler or Fly machine cron) makes a consistent SQLite snapshot (`VACUUM INTO`), encrypts it with `age` to a public recipient from `BUDGET_BACKUP_RECIPIENT`, uploads it to the bucket under `encrypted/`, keeps 30 daily + 12 monthly. Restore steps and a restore test (decrypt with a test key) in `docs/ops.md` and CI. The owner generates the age key pair offline; never in the repo or CI.
6. **B6** Rate limiter: key IPv6 by /64, cap the map (e.g. 10.000 keys, evict oldest), a global per-limiter ceiling; tests.
7. **B7** Dockerfile chown only `/data`, `/app` root-owned; `umask 077` in the entrypoint; revoke the previous session on re-login from the same device; re-set the cookie when the sliding expiry extends; ip hash as HMAC with the pepper; `Permissions-Policy` header (camera, microphone, geolocation, payment, usb = ()).

Never log secrets, codes or full IPs. Owner actions (new secrets `BUDGET_PEPPER`, `BUDGET_BACKUP_RECIPIENT`, key generation with `age-keygen`, where to store the private key offline) go into the PR description as exact commands.

Acceptance: `npm run check` and e2e green; new tests for each item; B1–B7 ticked in `docs/ROADMAP.md`.
