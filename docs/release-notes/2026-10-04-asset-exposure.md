# Historical exposure foundation — PR1

Security classification now uses inclusive effective-dated weighted sets. Reassignments preserve earlier allocation reports; mixed products conserve cents using largest remainder. Portfolio, R13/rebalancing, savings proposals, report 4.2, class performance and export labels share the resolver.

Validated atomic API replacement and existing single-class editing are audited and undoable, including same-day replacement. The instrument editor allows choosing the effective day, default today. CSV export includes version completeness and weighted history.

Migration preserves source rows and assumes each legacy class from its earliest trade/holding (creation day otherwise), labelled `legacy_assumed_from_first_record`; this is compatibility evidence, not historical certainty. Synthetic full-schema migration, repeated application and snapshot restore are tested. Production backup/count/value reconciliation is required before deployment.

Settings-page implementation, target-policy changes, risk/leverage, allocation quality and the iPhone panel fix are subsequent PRs. See [scope and acceptance](../asset-exposure.md).
